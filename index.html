A small cloud lesson · 01

Your first website, in the cloud.

A regular HTML page can live somewhere extraordinary. Meet Amazon S3: a simple way to put your static site on the internet.

See how it works ↓

NO SERVERS TO MANAGE  /  JUST FILES

The simple version

A bucket for your website files.

A static site is made from files that are ready to serve: HTML, stylesheets, images, and scripts. S3 stores those files and can return them when someone visits your site.

Under the hood

Three steps. One website.

No app server, no build pipeline required. Your browser asks for a file, and S3 sends it back.

01 / YOUR FILES</>

Make a page

Write your HTML, CSS, and images. The browser already knows how to use them.

02 / AMAZON S3▤

Store it in a bucket

Upload the files to an S3 bucket and enable static website hosting.

03 / THE WEB↗

Share the endpoint

Someone opens your website endpoint. S3 serves the index document to their browser.

Ready when you are

From your folder to your bucket.

Once your bucket is configured, the AWS CLI can sync a local site folder to it. Replace the example bucket name with yours.

  • ✓Create an S3 bucket in your AWS account.
  • ✓Enable static website hosting and set index.html as the index document.
  • ✓Install and configure the AWS CLI with your account credentials.
TERMINAL  /  DEPLOY 
$ aws s3 sync ./site s3://YOUR_BUCKET --delete

This syncs the contents of ./site. The --delete flag removes remote files that are no longer in your local folder.

i

A note before you publish: S3 website endpoints are HTTP-only and require public access to the site files. That can work for a learning demo. For a production site, keep the bucket private and serve it through CloudFront using an S3 REST origin for HTTPS.
